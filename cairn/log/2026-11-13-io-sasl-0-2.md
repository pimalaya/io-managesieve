# io-sasl 0.2

The crate moves from io-sasl 0.1 to io-sasl 0.2.0, published on 2026-11-13, and takes what the family audit of the same day left for this bump.

**The dependency.** The requirement is `0.2` in the manifest and in the fuzz package, and both lockfiles hold 0.2.0 alone (0.1.0 and 0.1.1 before). It brings base64-codec and simd-cpu into the graph, for the SCRAM messages. The `saslprep` feature this crate named is gone from io-sasl, which now prepares the credentials of PLAIN and SCRAM in every build, so the manifest names no feature on the dependency.

**Rust 1.89.** io-sasl 0.2 and base64-codec declare it, and `cargo update` said so while locking them against the 1.88 declared here. `rust-version` is 1.89, the one io-sasl, io-imap and io-smtp already declare.

**The SCRAM bounds are reachable.** `SaslScram::new` takes a `SaslScramOptions`, the floor and the ceiling of the iteration count a server may announce. `ManagesieveAuthenticateOptions` and `ManagesieveSessionOpenOptions` each gain a `scram` field of that type behind the `scram` feature, the session handing its own to the exchange it runs, so the std client reaches it through `ManagesieveClientStdConnectOptions::session`. The default is io-sasl's, 4096 to five million. The mechanism is built by a private method of the options, a constructor taking them leaving an unused argument in a build without `scram`.

One test, at the session level since it crosses both structs: with a ceiling of 10,000, a server-first-message announcing `i=4294967295` is answered with the `"*"` cancellation and the session completes with `IterationCountTooHigh { count: 4294967295, max: 10000 }`. A derivation of that many rounds would not return, so the test ending is the proof none ran.

**What else changes for a caller**, with no code here: SCRAM refuses a client nonce shorter than 18 bytes or holding a comma, a count that is not a positive decimal number and the reserved `m=` attribute, and a NUL in a PLAIN field fails as a preparation error. The nonce `connect` draws is 24 alphanumeric bytes and passes.

**Breaking**: the io-sasl types in this crate's API are those of 0.2 (`Sasl`, the credential structs, the mechanism errors `ManagesieveAuthenticateError` wraps and their new variants), and the new `scram` field breaks a literal naming every field of either options struct. Two such literals were in the tree, a unit test and examples/std_coroutine.rs. Both build with and without `scram`, where a `..Default::default()` is refused by clippy as a needless update, so they name the field under the feature.

Verified: 114 unit tests, 13 integration tests and 17 doctests green with every feature, the suite green with no default features, `client` alone, `url` alone, `scram` alone and the default set, clippy clean with every feature and with none, the build green with no default features, and the fuzz package type-checked against its new lockfile.

Spec updated: `authentication` (ADDED: "SCRAM iteration bounds"), `packaging` (MODIFIED: "SASL features").
